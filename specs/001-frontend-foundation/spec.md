# Feature Specification: 前端地基（登录、角色化应用壳与独立演示能力）

**Feature Branch**: `001-frontend-foundation`（待创建）

**Created**: 2026-11-14

**Status**: Draft

**Input**: User description: "按《GreenMind 开发规格书（执行版）》P1 阶段（第 1—2 周）实现前端地基：登录 + 角色化布局 + 路由守卫 + 演示数据机制 + 监控大屏骨架，使前端在后端未就绪时也能独立开发与演示。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登录与会话保持 (Priority: P1)

系统用户（管理员、工程师、查看者）打开系统进入登录页，输入用户名和密码后进入工作台，
顶栏显示自己的真实姓名。刷新页面后会话仍然有效；点击退出后回到登录页，会话被清空。

**Why this priority**: 登录是所有业务的入口，没有它其他任何页面都无法使用；也是第 1—2 周与后端登录接口联调的第一个契约点。

**Independent Test**: 使用演示账号（admin / engineer1 / engineer2 / viewer）分别登录、刷新、退出，全程可独立验证，不依赖任何业务页面实现。

**Acceptance Scenarios**:

1. **Given** 未登录状态，**When** 输入正确的用户名密码并提交，**Then** 进入工作台，顶栏显示该账号的真实姓名。
2. **Given** 已登录状态，**When** 刷新浏览器页面，**Then** 仍保持登录，无需重新输入密码。
3. **Given** 已登录状态，**When** 点击退出，**Then** 会话被清空并回到登录页，再访问受保护页面会要求重新登录。
4. **Given** 登录页，**When** 输入错误的密码或不存在的用户名，**Then** 显示统一的可读错误提示（不区分"用户不存在"与"密码错误"），停留在登录页。
5. **Given** 会话已过期或失效，**When** 发起任何业务请求，**Then** 系统统一清空会话并跳转登录页，不出现半登录状态。

---

### User Story 2 - 按角色导航与访问控制 (Priority: P1)

不同角色登录后看到不同的菜单：查看者只看到只读业务入口，看不到任何编辑/新建/审批类操作；
用户管理入口仅管理员可见。任何人手动输入无权限页面的网址都会被重定向，未登录访问受保护
页面会先跳登录页、登录后回到原目标页。

**Why this priority**: 权限是规格书的硬性验收项（viewer 写操作一律拒绝），必须在所有业务页面开发之前就位，后续每个页面直接复用，避免返工。

**Independent Test**: 用三种角色账号分别登录，核对菜单项、页面内写入口数量，并手动输入越权网址验证重定向；无需任何业务功能实现。

**Acceptance Scenarios**:

1. **Given** viewer 已登录，**When** 查看导航菜单和任意页面，**Then** 写操作入口（新建/编辑/删除/确认/审批等）数量为 0。
2. **Given** 非 admin 已登录，**When** 手动输入用户管理页网址，**Then** 被重定向到其有权限的页面。
3. **Given** 未登录，**When** 直接访问任一受保护页面网址，**Then** 跳转登录页；登录成功后回到原目标页。
4. **Given** admin 已登录，**When** 查看菜单，**Then** 可见全部入口，包括用户管理。

---

### User Story 3 - 应用壳与页面骨架 (Priority: P2)

登录后进入统一应用壳：左侧菜单 + 顶栏（真实姓名 + 退出）+ 内容区。九个业务页面
（监控大屏、告警、预测、工单、设备、巡检、报表、助手、用户管理）全部可通过菜单或网址到达；
尚未实现的页面显示明确的"建设中"占位，不展示虚构业务数值。监控大屏以骨架形态先行交付：
设备选择、污染物指标卡（当前值对比标准值、超标高亮）、24 小时趋势图，用演示数据渲染。
登录页与手机巡检页使用无侧边栏的空白布局。

**Why this priority**: 应用壳和路由骨架是后续每个业务 feature 的挂载点；大屏骨架让第 1—2 周阶段末有可演示的监控雏形，对应规格书 P1 交付"登录 + 布局 + 大屏骨架（mock）"。

**Independent Test**: 登录后逐一点击全部菜单项验证可达性与占位标识；在演示数据模式下检查大屏骨架的设备切换、指标卡超标高亮与趋势图渲染。

**Acceptance Scenarios**:

1. **Given** 任一角色已登录，**When** 逐一访问九个业务页面路由，**Then** 全部可达、无死链；未实现页面显示"建设中"占位而非空白或报错。
2. **Given** 大屏骨架页，**When** 切换设备，**Then** 指标卡与趋势图随之刷新为对应设备的演示数据。
3. **Given** 演示数据中某污染物超过标准值，**When** 查看对应指标卡，**Then** 该卡片以超标态高亮显示。
4. **Given** 手机浏览器访问巡检路由，**When** 页面加载，**Then** 呈现无侧边栏的空白布局（巡检功能本身属后续 feature）。

---

### User Story 4 - 无后端独立演示与逐模块切换 (Priority: P2)

后端尚未就绪时，前端可完全依靠演示数据运行：登录、导航、大屏骨架全流程可演示。
演示数据与后端接口契约结构一致；后端每交付一个模块，前端可单独把该模块切换为真实数据，
其余模块继续使用演示数据，互不影响。

**Why this priority**: 这是三人并行开发的关键机制——A 照 Swagger + mock 开发，不等后端实现（规格书第二节并行规则）；没有它前端会被后端进度阻塞。

**Independent Test**: 在后端完全停机的情况下走通"登录 → 导航 → 大屏骨架"演示；随后仅将一个模块指向真实接口（或契约桩），验证其余模块演示不受影响。

**Acceptance Scenarios**:

1. **Given** 后端服务完全不可用且处于演示数据模式，**When** 执行登录到查看大屏骨架的完整流程，**Then** 全流程正常，无报错、无空白页。
2. **Given** 某模块后端已交付，**When** 仅将该模块切换为真实数据，**Then** 该模块走真实接口，其余模块仍用演示数据正常工作。
3. **Given** 真实数据模式下后端临时不可用，**When** 请求失败，**Then** 向用户展示可读的错误提示，页面不崩溃。

---

### Edge Cases

- 会话恰好在 24 小时有效期边界过期：下一次请求触发统一登出跳转，不出现卡死的半登录状态。
- 演示模式下刷新页面：登录会话与演示模式状态保持。
- 演示数据与接口契约结构不一致：以契约（Swagger）为准修正演示数据，而不是让页面适配错误结构。
- 浏览器直接访问登录页时已登录：进入工作台，不重复登录。
- 同一浏览器切换不同角色账号：菜单与写入口立即按新角色刷新，无上一角色残留。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须提供用户名/密码登录；成功进入工作台并显示用户真实姓名；失败显示统一可读错误提示并停留在登录页。
- **FR-002**: 登录会话必须在页面刷新后保持；退出必须清空会话并回到登录页。
- **FR-003**: 未登录访问受保护页面必须重定向到登录页，登录成功后回到原目标页。
- **FR-004**: 会话过期或失效时，系统必须统一清空会话并跳转登录页。
- **FR-005**: 导航菜单必须按角色过滤：viewer 仅见只读业务入口；用户管理入口仅 admin 可见。
- **FR-006**: 通过网址直接访问无权限页面必须被重定向到其有权限的页面。
- **FR-007**: viewer 在任何页面不得看到写操作入口（新建/编辑/删除/确认/审批等）。
- **FR-008**: 应用壳必须包含左侧菜单、顶栏（真实姓名 + 退出）与内容区；登录页与巡检页使用无侧边栏空白布局。
- **FR-009**: 九个业务页面路由（监控大屏、告警、预测、工单、设备、巡检、报表、助手、用户管理）必须全部可达；未实现页面显示明确"建设中"占位，不得展示虚构业务数值。
- **FR-010**: 监控大屏骨架必须用演示数据呈现：设备选择、各污染物指标卡（当前值 + 标准值、超标高亮）、24 小时趋势图；切换设备时联动刷新。
- **FR-011**: 前端必须能在无后端的演示数据模式下运行并完成登录、导航、大屏骨架的完整演示。
- **FR-012**: 演示数据结构必须与后端接口契约一致；每个业务模块必须可独立切换演示数据/真实数据，切换不影响其他模块。
- **FR-013**: 接口错误必须以统一的可读消息提示用户；列表类页面必须使用统一的分页交互。
- **FR-014**: 交付必须通过生产构建；所有路由可达；演示流程中浏览器控制台无报错。

### Key Entities

- **用户会话**: 登录凭证与用户身份（ID、用户名、真实姓名、角色），有效期内跨刷新保持，退出或过期即失效。
- **角色**: admin / engineer / viewer 三种，决定菜单可见性与写操作入口的显隐；后端另有强制校验（本 feature 只做前端层）。
- **演示数据集**: 与接口契约结构一致的样例数据，至少覆盖登录账号与大屏骨架所需的设备、污染物指标、趋势序列。
- **导航菜单**: 按角色过滤后的页面入口集合，含九个业务页面。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四个演示账号（admin、engineer1、engineer2、viewer）均能在 10 秒内完成登录，并看到与角色一致的菜单。
- **SC-002**: 刷新后会话保持成功率 100%；退出与会话过期均 100% 回到登录页。
- **SC-003**: viewer 可见的写操作入口数量为 0；非 admin 访问用户管理页被重定向的比例为 100%。
- **SC-004**: 九个业务路由可达率 100%，无死链；大屏骨架在演示数据下正确渲染并随设备切换刷新。
- **SC-005**: 后端完全停机时仍可完成"登录 → 导航 → 大屏骨架"演示；单模块切换真实数据后其余模块演示不受影响。
- **SC-006**: 生产构建一次通过；完整演示流程中控制台报错数为 0。

## Assumptions

- 基准为《GreenMind 开发规格书（执行版）》（3 人 × 10 周）；仓库内四人讨论稿未采纳为基准。
- 本 feature 对应 P1 阶段（第 1—2 周）前端交付；各业务页面的完整实现属于后续 feature（002 监控大屏、003 告警、004 工单、005 预测、006 设备、007 巡检 H5、008 助手、009 报表与用户管理）。
- 后端 D 在第 1 周交付全部表模型与路由桩（Swagger 可见）；登录与用户管理接口契约按规格书第四节执行。
- 演示账号来自后端演示数据脚本：admin / engineer1 / engineer2 / viewer，密码均为 123456；演示数据模式下前端使用与该契约一致的本地账号数据。
- 技术栈、目录结构与统一接口约定遵循项目宪法（.specify/memory/constitution.md），本 spec 不重复。
- 大屏骨架仅含静态演示数据渲染；时间回放滑块、SSE 告警横幅等交互属于 002 监控大屏 feature。
