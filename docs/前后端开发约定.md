**版本**: v1.0 | **日期**: 2026-11-14 | **维护**: A（前端）整理，C/D 共同遵守

**基准**: 《GreenMind 开发规格书（执行版）》（3 人 × 10 周）第四节"统一约定" + 项目宪法
（`.specify/memory/constitution.md`）。本文档是规格书的提炼与强调，**与规格书冲突时以规格书为准**；
变更必须先改规格书再改代码。仓库内《四人并行开发方案.md》为讨论稿，不采纳。

**阅读对象**: C（数据与 AI）、D（业务与基础）。核心原则：**前端按 Swagger + mock 并行开发，
后端任何字段/结构/状态码/事件名的改动都会直接导致前端返工，必须提前通知。**

## 1. 统一接口约定（强制，不得私自变更）

### 1.1 路由前缀与跨域

| 项 | 约定 | 前端依赖 |
|---|---|---|
| 路由前缀 | 所有业务接口统一挂 `/api`（main.py 注册 9 个 router，前缀 `/api`） | axios `baseURL=/api`；vite 代理 `/api → http://localhost:8000` |
| CORS | 允许 `http://localhost:5173` | 前端 dev server 端口 5173，跨域放行才能联调 |
| 后端端口 | 8000（uvicorn） | vite 代理目标 |

### 1.2 认证

- `POST /api/auth/login` 返回 `{token, user:{id, username, real_name, role}}`。
- JWT **HS256，24h 过期**；其余接口请求头 `Authorization: Bearer <token>`。
- `deps.get_current_user` 解析 token，`require_role(...)` 校验角色（D 负责 security.py / deps.py）。
- **登录失败统一返回 401 + `{"detail":"用户名或密码错误"}`，不区分"用户不存在"与"密码错误"**
  （安全要求 + 前端统一提示）。
- `real_name` 必填：前端顶栏直接显示真实姓名。

### 1.3 权限（双层保障，后端是最终防线）

| 角色 | 权限 |
|---|---|
| admin | 全部（含用户管理、设备 CRUD、报表生成、预测刷新、工单审批） |
| engineer | 接/完工单、提交巡检、手动建告警/工单 |
| viewer | **只读，写操作一律 403**（登录和助手聊天除外） |

- **前端按角色隐藏写入口只是第一层；后端必须 `require_role` 强制校验，两层缺一不可（宪法 V）。**
- 不能因为"前端已经隐藏按钮"就省略后端校验——直接调接口必须被拒。
- 工单状态机操作还有身份约束：accept/complete 仅 assignee 或 admin，approve 仅 admin。

### 1.4 响应与错误

| 场景 | 约定 | 前端依赖 |
|---|---|---|
| 成功 | 直接返回 JSON（不包 envelope） | axios 响应拦截器按裸 JSON 处理 |
| 分页 | `{items, total, page, page_size}` | PageTable 组件按此四字段渲染 |
| 错误 | `HTTPException`，body `{"detail": "消息"}` | 拦截器读 `detail` 弹 ElMessage |
| 状态码 | 400 参数错 / 401 未登录 / 403 无权限 / 404 不存在 | **401 → 前端清会话跳登录；403 → 提示无权限** |

> ⚠️ 错误 body 必须是 `{"detail": "..."}`，不要用 `{message}`/`{error}`/`{msg}` 等其他键，
> 否则前端取不到提示文案。401 必须真实返回 401（不要 200 包错误码），否则前端无法触发统一登出。

### 1.5 分页与时间

- 分页参数：`page` 默认 1，`page_size` 默认 20、**最大 100**。
- 时间参数与返回：**ISO 8601（`YYYY-MM-DDTHH:mm:ss`）**。前端 `format.ts` 按此解析显示。
- 历史查询区间语义按规格书执行；不要返回带时区偏移的字符串导致前端解析不一致。

### 1.6 SSE（实时推送）

- `Content-Type: text/event-stream`。
- **事件名固定**：`alarm`（告警横幅）/ `token`（助手流式）/ `done`（助手结束）。
- `data` 为 **JSON 字符串**。前端 `sse.ts` 按事件名监听，改名即失效。
- 告警 SSE：`GET /api/alarms/stream`，`event:alarm`，`data:{id, level, device_id, pollutant, value, summary}`。
  验收要求"告警产生后 5 秒内横幅出现"。
- 助手 SSE：`POST /api/assistant/chat`，`event:token` `data:{text}`，`event:done` `data:{message_id}`。
- 需支持断线重连后的补发或重新查询（前端 store 会自动重连）。

### 1.7 上传与静态资源

- `POST /api/upload`（multipart，字段名 **`file`**）→ `{"path": "/uploads/20261114_a1b2c3.jpg"}`。
- 静态挂载 `/uploads`；图片 **≤5MB，仅 jpg/png**。
- 前端巡检照片/签名回显依赖返回的 `path` 可直接访问；签名用原生 canvas 生成图片后走同一上传接口。

### 1.8 操作日志

- 中间件对**所有非 GET 请求**写 `operation_log`（`user_id`、`action=方法+路径`、`target`、`detail=参数摘要`）。
- LLM 每次调用也写 operation_log（模型、tokens、耗时）——C 负责。

### 1.9 配置与密钥

- `.env`：`DATABASE_URL`、`JWT_SECRET`、`LLM_API_KEY`、`LLM_BASE_URL`（默认 https://api.deepseek.com）、
  `LLM_MODEL`（默认 deepseek-chat）、`LLM_FALLBACK_MODEL`（默认 qwen-plus）、`UPLOAD_DIR`（默认 ./uploads）。
- **密钥不得提交仓库**；提供 `.env.example` 占位。

## 2. 并行协作规则（宪法 IV）

1. **第 1 周 D 必须交付全部 models + 路由桩**（FastAPI 自动生成 Swagger，`/docs` 可见）。
   这是 A 并行开发的前提——A 照 Swagger + mock 开发，不等后端实现。**桩延期 = 前端被阻塞。**
2. **mock 结构必须与 Swagger 一致**。后端定字段时即冻结契约；前端 mock 照此做。
3. **后端每交付一个模块，通知 A 切换对应模块**（前端用 `VITE_REAL_MODULES=auth,data,...` 逐模块切真实接口，
   其余继续 mock）。不要等全部完成才一次性联调。
4. **接口改动必须提前通知搭档**（A↔C/D）；关键接口变更通知全部使用方，并提供兼容方式与迁移说明。
5. **每两周阶段末联调一次**（P1 周 2 / P2 周 4 / P3 周 6 / P4 周 8 / P5 周 10），不得等到最后才首次集成。
6. 两个内部调用是**同进程函数，不是 HTTP**：C 告警引擎 → D `workorder_svc.create_from_alarm(alarm)`；
   D 健康度/报表 → C `llm.chat()`。公共底座唯一：LLM 封装归 C，登录/权限归 D，互相复用不重复造。

### 3.3 关键字段枚举（前后端必须一致）

- `role`: `admin | engineer | viewer`
- `condition_flag`: `normal | startup | shutdown | fault`
- `alarm.level`: `yellow | orange | red`；`alarm.status`: `pending | acked | closed`
- `work_order.status`: `pending | processing | accepting | closed`；`priority`: `low | medium | high | urgent`
- `device.status`: `running | stopped | maintenance`
- 标记位 `report_flag / comm_flag / exceed_flag / zero_flag`: 0/1
- 污染物字段：`pm / so2 / nox / co / hcl`，各 `_real（实测）/_std（折算）/_limit（标准）`，单位 mg/m³

## 4. LLM 输出 JSON 契约（C 负责，前端按结构渲染）

前端诊断抽屉/预测图/健康度仪表盘**直接按下列 JSON 字段渲染**，C 的 prompts.py 必须保证输出结构稳定
（json_mode=True），字段缺失或改名会导致前端渲染空白或报错。

| 提示词 | 输出结构 | 约束 |
|---|---|---|
| 5.1 告警诊断 | `{root_causes:[{cause,confidence}], measures:[], estimated_recovery_minutes, summary}` | root_causes≤3，confidence 0—1，summary≤200 字 |
| 5.2 趋势预测 | `{hours:[{ts,value,exceed_prob}], drivers:[], confidence}` | hours 固定未来 6 点，value≥0，exceed_prob 0—1 |
| 5.3 健康度 | `{score, factors:[{name,impact}], suggestion}` | score 0—100 整数，suggestion≤300 字 |
| 5.4 月报 | Markdown 纯文本 | 固定四章节：数据概述/超标事件说明/设备运行情况/改进建议；数字必须来自给定统计 |
| 5.5 助手 | tools + stream 文本 | 4 个查库 tool；流式输出 |

- LLM 封装行为：超时 60s；超时/5xx 重试 2 次（退避 1s/3s）；429 或重试失败切备用模型。
- **模型不可用不得阻塞告警/工单/查询**；前端 AI 区显示"暂不可用"，核心链路照常。

## 5. 后端易踩坑清单（会直接导致前端返工/报错）

1. **错误 body 键名不是 `detail`** → 前端弹不出提示。
2. **未登录返回 200 包错误码而非 401** → 前端无法统一登出，出现半登录态。
3. **viewer 写操作后端没拦（只靠前端隐藏）** → 越权成功，验收第 7 条失败。
4. **分页返回结构不是 `{items,total,page,page_size}`** → PageTable 渲染失败。
5. **时间格式非 ISO 8601 / 带时区偏移** → 前端解析错乱、趋势图横轴异常。
6. **SSE 事件名改动或 data 不是 JSON 字符串** → 告警横幅/助手流式失效。
7. **登录错误区分"用户不存在/密码错误"** → 违反安全约定，前端提示文案不一致。
8. **字段命名/枚举与 Swagger 不一致就交付** → 前端 mock 与真实接口对不上，切换即崩。
9. **第 1 周 Swagger 桩延期** → 前端并行前提缺失，整体被阻塞。
10. **接口改动不通知 A** → 联调时才发现，返工。
11. **上传返回 path 不可直接访问 / 未挂 /uploads** → 巡检照片签名无法回显。
12. **CORS 未放行 5173** → dev 联调全部跨域失败。
13. **LLM 输出 JSON 结构不稳定** → 诊断/预测/健康度渲染空白。
14. **报表 generate 同步耗时无预期** → 前端需 loading，接口应明确可能 30s。

## 7. 验收对齐（前端总验收依赖后端的部分）

前端总验收（宪法 VI）：`npm run build` 通过、所有路由可达、角色守卫生效、控制台无报错。
其中**角色守卫与越权 403 必须后端配合**才能端到端验证：

- viewer 调写接口 → 后端 403（前端隐藏 + 后端拒绝双层）。
- 非 admin 调 `/api/users`、设备 CRUD、报表生成、预测刷新 → 403。
- 工单越权操作（非 assignee accept/complete、非 admin approve）→ 403。
- 端到端演示链路：超标→告警→AI 诊断→自动工单→接单/完成/关闭；月报生成+导出；助手数据问答。
