## 1. 交付范围与技术栈

- 页面：登录 / 监控大屏 / 告警中心 / 趋势预测 / 智能工单 / 设备资产 / 智能巡检（H5）/ 台账报表 / 智能助手 / 用户管理。
- 技术栈：Vue 3 + Vite 5 + TypeScript + Element Plus + ECharts 5 + Pinia + Vue Router + axios + markdown-it + html5-qrcode；手写签名用原生 canvas。
- 构建脚本：`vue-tsc --noEmit && vite build`；产物输出到 `frontend/dist/`。

## 2. 环境要求

- Node.js ≥ 18、npm ≥ 9（仓库带 `package-lock.json`，可用 `npm ci` 复现依赖）。
- 现代浏览器（Chrome / Edge 最近两个大版本）。
- 巡检页面向移动端：相机扫码需 HTTPS 或 `localhost`；无相机环境自动退化为手动选设备。

## 3. 启动与构建

```bash
cd frontend
npm install            # 或 npm ci

npm run dev            # 开发服务器 → http://localhost:5173（默认演示模式）
npm run build          # 类型检查 + 生产构建 → dist/
npm run preview        # 预览构建产物 → http://localhost:4173
```

开发服务器代理（`vite.config.ts`）：

| 前缀 | 目标 | 说明 |
|---|---|---|
| `/api` | `http://localhost:8000` | axios `baseURL=/api` |
| `/uploads` | `http://localhost:8000` | 巡检照片等静态文件 |

**环境变量在构建/启动时注入**（Vite 的 `import.meta.env`），修改后需重启 dev 或重新 build。仓库只有 `frontend/.env.development` 与 `.env.example`，**没有 `.env.production`**：生产构建若未显式提供变量，`VITE_USE_MOCK` 取默认值 `true`，即仍是演示数据。

**部署提示**：路由使用 `createWebHistory`，nginx 需配置 SPA 回退（如 `try_files $uri $uri/ /index.html;`），并把 `/api`、`/uploads` 反代到后端。

## 5. 演示数据模式与逐模块切换

| 变量 | 默认 | 说明 |
|---|---|---|
| `VITE_USE_MOCK` | `true`（`frontend/.env.development`） | 全局演示数据开关；仅 `'false'` 时关闭 |
| `VITE_REAL_MODULES` | 空 | 逗号分隔的模块名，强制走真实接口，覆盖全局 mock |

**模块名**（与 `src/api/*.ts` 一一对应，共 10 个）：
`auth`、`data`、`alarm`、`prediction`、`workorder`、`device`、`inspection`、`report`、`assistant`、`user`

**规则**（`src/api/mock/index.ts`）：

- `VITE_USE_MOCK=false` → 所有模块走真实接口；
- `VITE_USE_MOCK=true` → 仅 `VITE_REAL_MODULES` 中列出的模块走真实，其余继续 mock；
- 顶部栏“演示数据 / 真实接口”标识只反映 `VITE_USE_MOCK`，不细分模块。

**示例**（后端已交付登录与数据接口时）：

```bash
VITE_USE_MOCK=true
VITE_REAL_MODULES=auth,data
```

建议切换顺序：`auth,data` → `alarm,workorder` → `prediction,device,inspection` → `report,assistant,user`。mock 契约见各 feature 的 `contracts/`；与后端 Swagger 不一致时以后端为准修 mock，不改页面。

**mock 行为说明**：

- 数据来自 `src/api/mock/*.json`，模块内存在内存中增删改，**刷新页面后恢复初始样例**；智能助手会话按用户持久化在 `localStorage["gm_assistant_<userId>"]`。
- 网络延迟统一约 320ms（个别接口 150ms / 900ms），便于观察 loading 态。
- 告警 SSE 在 mock 下由本机定时器模拟：首条约 2.5 秒后出现，之后每 9 秒一条；横幅最多 3 条，不自动消失，可点击跳转 `/alarms?focus=<id>` 或手动关闭。
- 真实模式下：告警流用 `EventSource('/api/alarms/stream')`，断线 3 秒重连；助手对话用 `fetch POST /api/assistant/chat`，携带 `Authorization: Bearer <token>` 并解析 `data:` 行内 JSON。

## 7. 统一接口约定（摘要）

详见 [`docs/前后端开发约定.md`](./前后端开发约定.md)。要点：路由前缀 `/api`；JWT `Authorization: Bearer`；分页 `{items,total,page,page_size}`；错误体 `{"detail"}` 对应 400/401/403/404；时间 ISO 8601；告警流事件名 `alarm`；上传仅 jpg/png 且 ≤5MB；权限前端隐藏 + 后端 `require_role` 双层校验。

## 8. 已知限制与注意事项

- **PDF 导出**：mock 模式打开打印预览窗口，由浏览器“另存为 PDF”；真实模式下载后端生成文件。mock 的 Excel 为可打开的 `.xls`（HTML 表格格式）。
- **告警 SSE 鉴权**：`EventSource` 不能自定义请求头，真实模式下 `/api/alarms/stream` 未携带 token；联调时需后端支持查询参数或 cookie 鉴权（助手流用 `fetch`，不受此限制）。
- **mock 数据不落库**：除助手会话外，刷新页面即恢复初始样例；多人同时演示会各自独立。
- **巡检提交与 viewer**：巡检页对 viewer 可见，提交时由校验返回 403（不产生数据）；如需完全隐藏入口，可在联调阶段补充前端禁用逻辑。
- **构建提示**：`npm run build` 会输出一条 Vite 提示（`router/index.ts` 同时被静态与动态导入，动态拆包不生效），不影响构建结果。
- 演示数据为样例，不代表现场事实；超标与预测均仅供运维参考，不构成监管合规判定。
